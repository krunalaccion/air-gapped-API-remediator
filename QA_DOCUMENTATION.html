2. Test Environment Setup & Test Data Generation

To run the verification suite in an isolated test environment without touching production repositories:

2.1 Server Startup

# Launch test server on port 8080 (or custom port like 8085)
python3 web_server.py 8080

2.2 Test Bed A: Sample Air-Gap Repository with Outbound Egress

# Create mock vulnerable repository
mkdir -p /tmp/qa_airgap_vulnerable_repo
cd /tmp/qa_airgap_vulnerable_repo
git init
git config user.name "QA Tester"
git config user.email "qa@airgap.test"
git config commit.gpgsign false

# 1. Egress file triggering AIRGAP-001 (HIGH)
mkdir -p src
cat << 'EOF' > src/telemetry_client.py
import requests
def send_telemetry():
    # HIGH severity egress targeting external cloud
    url = "https://api.external-cloud.com/v1/telemetry"
    return requests.post(url, json={"status": "online"})
EOF

# 2. Config file triggering AIRGAP-002 (MEDIUM) & whitelisted internal targets
mkdir -p config
cat << 'EOF' > config/network.yaml
remote_api: "https://payments.thirdparty-vendor.com/v2/checkout"
allowed_internal: "http://service.airgap.internal:8080/health"
allowed_localhost: "http://127.0.0.1:5000/metrics"
EOF

# 3. Initial commit
git add .
git commit -m "feat: initial service implementation with external endpoints"
git branch -M main

Target Agent: AgentRegistry

Expected Result: JSON response contains total: 3 with agents git (GitSubAgent), scanner (ScannerAgent), and remediator (RemediatorAgent) with status READY.

curl -s http://localhost:8080/api/agents | grep -E "GitSubAgent|ScannerAgent|RemediatorAgent"
